## Overview

Add Traefik as the single ingress point for the stack (Architecture §6.1, §6.2): it terminates TLS, routes to `web`/`api`, and is the only container that publishes ports to the host.

## User Story

As an operator, I want one reverse proxy handling TLS and routing, so that the API and web app are never directly exposed and every response carries the required security headers.

## Acceptance Criteria

### Functional Requirements

- [ ] Traefik container added to `docker-compose.yml`, publishing host ports 80 and 443 — the only container in the stack that does so.
- [ ] Routing rule: requests to `/api/*` go to the `api` service; everything else goes to `web`.
- [ ] TLS certificates issued/renewed automatically via ACME (Let's Encrypt) in `staging`/`prod`; `dev` uses a self-signed or plain-HTTP override (documented in `docker-compose.dev.yml`).
- [ ] Response headers on every route include `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, a frame-ancestors/`X-Frame-Options` restriction, and a CSP restricting script/style origins to the app's own bundles (Architecture §5.4).
- [ ] CORS is restricted to the deployed PWA origin(s) per environment (configured on the `api` service, enforced at the FastAPI layer, documented here since Traefik is the entry point).

### Non-Functional Requirements

- [ ] Performance: N/A at this scale.
- [ ] Accessibility: N/A.
- [ ] Error handling: a certificate renewal failure must be visible in Traefik's logs, not silently ignored.

## Technical Implementation

### Files to Create/Modify

| File | Action | Purpose |
|------|--------|---------|
| `docker-compose.yml` | Modify | Add `proxy` (Traefik) service, publish 80/443 |
| `infra/deployment/traefik/traefik.yml` | Create | Static Traefik config (entrypoints, ACME resolver) |
| `infra/deployment/traefik/dynamic.yml` | Create | Dynamic config: routers, middlewares (security headers) |
| `docker-compose.dev.yml` | Modify | Dev override: HTTP-only or self-signed cert, no ACME |

### Key Components

1. **Traefik static config** - Defines `web`/`websecure` entrypoints and the ACME certificate resolver.
2. **Traefik dynamic config / Docker labels** - Router rules (`PathPrefix(/api)` → `api` service, default → `web` service) and a headers middleware applied to all routers.
3. **Security headers middleware** - One shared Traefik middleware definition reused across every router so headers can't drift between routes.

### Dependencies

- STORY-001-01 (api/web containers must exist to route to).
- STORY-001-02 (proxy itself has no dependency on the data services, but the full stack does).

### Code Structure Suggestions

```yaml
# infra/deployment/traefik/dynamic.yml (excerpt)
http:
  middlewares:
    security-headers:
      headers:
        stsSeconds: 31536000
        contentTypeNosniff: true
        frameDeny: true
        contentSecurityPolicy: "default-src 'self'; script-src 'self'; style-src 'self'"
  routers:
    api:
      rule: "PathPrefix(`/api`)"
      service: api
      middlewares: [security-headers]
      tls:
        certResolver: letsencrypt
    web:
      rule: "PathPrefix(`/`)"
      service: web
      middlewares: [security-headers]
      tls:
        certResolver: letsencrypt
```

## Notes & Considerations

- Keep the security-headers middleware definition in one place and reference it from every router — duplicating header config per router is how these drift and rot.
- ACME requires a real domain and DNS pointed at the host in staging/prod; document the dev-mode fallback clearly so local development doesn't block on DNS/certs.
