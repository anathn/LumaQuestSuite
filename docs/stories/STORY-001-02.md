## Overview

Add the stateful services (PostgreSQL 16, Redis, MinIO) to the Compose stack from STORY-001-01, wired so only `api`/`worker` can reach them — never the host or the internet directly (Architecture §6.2).

## User Story

As a developer, I want Postgres, Redis, and MinIO running as containers reachable only from the app containers, so that later stories have persistent storage, a cache/broker, and object storage without any of them being exposed outside the stack.

## Acceptance Criteria

### Functional Requirements

- [ ] `postgres:16` container added to `docker-compose.yml` with a named, persistent volume; no host port published.
- [ ] `redis` container added with a named, persistent volume (for AOF/RDB durability of session data); no host port published.
- [ ] `minio` container added with a named, persistent volume; no host port published to the host in `staging`/`prod` overrides (dev override may publish the MinIO console port for local debugging only).
- [ ] `api` and `worker` containers can resolve and connect to `postgres`, `redis`, and `minio` by their Compose service name over the internal Docker network.
- [ ] Environment variables for connection strings (`DATABASE_URL`, `REDIS_URL`, `MINIO_ENDPOINT`/credentials) are read by `apps/api`/`worker` from the environment, not hardcoded.
- [ ] A `docker compose exec api ...` health check script confirms connectivity to all three services.

### Non-Functional Requirements

- [ ] Performance: N/A at this scale.
- [ ] Accessibility: N/A.
- [ ] Error handling: `api`/`worker` fail fast with a clear log message (not a silent hang) if a required connection string env var is missing at startup.

## Technical Implementation

### Files to Create/Modify

| File | Action | Purpose |
|------|--------|---------|
| `docker-compose.yml` | Modify | Add `postgres`, `redis`, `minio` services, volumes, and network |
| `docker-compose.dev.yml` | Create | Dev-only override (e.g., publish MinIO console port for local debugging) |
| `.env.example` | Create | Documents required env vars (`DATABASE_URL`, `REDIS_URL`, `MINIO_*`) without real secrets |
| `apps/api/app/config.py` | Create | Typed settings object (Pydantic `BaseSettings`) reading the above env vars |

### Key Components

1. **Docker network** - One user-defined bridge network in `docker-compose.yml`; `postgres`/`redis`/`minio` have no `ports:` mapping in the base file (only in the `dev` override, if at all).
2. **Settings module** - `apps/api/app/config.py` centralizes all connection strings so no other module constructs a DB/Redis URL itself.

### Dependencies

- STORY-001-01 (api/worker containers must exist to connect to these services).

### Code Structure Suggestions

```yaml
# docker-compose.yml (excerpt)
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - pg_data:/var/lib/postgresql/data
    networks: [internal]

  redis:
    image: redis:7
    volumes:
      - redis_data:/data
    networks: [internal]

  minio:
    image: minio/minio
    command: server /data
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
    volumes:
      - minio_data:/data
    networks: [internal]

networks:
  internal:
    driver: bridge

volumes:
  pg_data:
  redis_data:
  minio_data:
```

```python
# apps/api/app/config.py
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str
    redis_url: str
    minio_endpoint: str
    minio_access_key: str
    minio_secret_key: str

settings = Settings()
```

## Testing Requirements

### Unit Tests

- Test `Settings` raises a clear validation error when a required env var is missing.

### Integration Tests

- Test scenario: from inside the `api` container, open a connection to `postgres`, `PING` `redis`, and list buckets on `minio` — all three succeed.
- Test scenario: attempt to reach `postgres`/`redis`/`minio` from outside the Docker network (e.g., from the host) and confirm it's refused/unreachable in the `staging`/`prod`-style Compose file.

### Manual Testing

1. `docker compose up postgres redis minio api worker`.
2. `docker compose exec api python -c "..."` to confirm all three connections succeed.
3. `nc -zv localhost <port>` from the host for each service's default port — confirm connection refused for the non-dev override.
